## フェーズ 0：基盤

- Cargo ワークスペース（`shirabe-dsp`、`shirabe-ui`、`shirabe-plugin`、`xtask`）
- サンプルピークメーター（モノラル / ステレオ）
- テストオシレーター
- VST3、CLAP、スタンドアロンアプリのビルド
- GitHub Actions（fmt、clippy、テスト、Windows / Linux のバンドル、pluginval による VST3 検証）

完了条件は次のとおりです。

1. CI がすべて成功し、Windows 向けの成果物が生成される。
2. Windows のホストアプリケーションで VST3 を読み込み、音がそのまま通り、メーターが動く。
3. スタンドアロンアプリが起動し、テストオシレーターでメーターが動く。

Windows 11 での確認結果（2026-11-25）は次のとおりです。

| 項目 | 結果 |
|---|---|
| Visual C++ ランタイムが無い環境での起動 | 当初は起動できず、C ランタイムの静的リンクで修正済み |
| VST3 の読み込みとメーター表示（ステレオ） | 成功。テスト信号の L -18.0 / R -24.0 dBFS をそのまま表示 |
| pluginval（GUI テストを含む、ソフトウェア OpenGL 使用時） | 成功 |
| スタンドアロン（ダミーバックエンド、テストオシレーター） | 成功 |
| GPU のない環境でのエディター表示 | 失敗（[#1](https://github.com/My-MC/shirabe/issues/1)）→ フォークで修正済み |
| スタンドアロンの WASAPI 出力 | 失敗（[#2](https://github.com/My-MC/shirabe/issues/2)） |

## フェーズ 1：規格準拠の基本メーター

トゥルーピーク、VU、PPM（Type I / II）、ラウドネス（M / S / I / LRA）を実装し、同一画面で表示できます。
ラウドネスとトゥルーピークは、EBU の公式テスト音源で EBU Tech 3341 / 3342 の全ケースを確認しました。
表示は EBU Mode の要件（目盛り、単位、I と LRA の操作）に合わせています（[standards.md](standards.md)）。
スタンドアロンアプリは自前のオーディオ処理に置き換え、入力デバイスの選択画面を追加しました（[#2](https://github.com/My-MC/shirabe/issues/2)）。
PLR と、音声ファイルを再生しながらの測定は未実装です。

- トゥルーピーク（ITU-R BS.1770 Annex 2 を参照）
- ラウドネス：Momentary、Short-term、Integrated、LRA、PLR（ITU-R BS.1770、EBU Tech 3341 / 3342）
- 目標値プリセット：ARIB TR-B32、EBU R128、ATSC A/85、配信向け
- VU（IEC 60268-17）、PPM（IEC 60268-10）
- ホストの再生開始に連動した Integrated のリセット
- スタンドアロン専用 UI：オーディオデバイスの選択画面、音声ファイルを再生しながらの測定
- スタンドアロンのオーディオ処理を自前の実装に置き換え、デバイスのサンプルレートと任意のバッファサイズに対応（[#2](https://github.com/My-MC/shirabe/issues/2)）

完了条件は次のとおりです。

1. EBU Tech 3341 / 3342 の適合性テスト信号を使った自動テストがすべて許容範囲内に入る。
2. スタンドアロンアプリで、入力デバイスの選択と音声ファイルの再生測定ができる。
