## フェーズ 1：規格準拠の基本メーター

トゥルーピーク、VU、PPM（Type I / II）、ラウドネス（M / S / I / LRA）を実装し、同一画面で表示できます。
ラウドネスとトゥルーピークは、EBU の公式テスト音源で EBU Tech 3341 / 3342 の全ケースを確認しました。
表示は EBU Mode の要件（目盛り、単位、I と LRA の操作）に合わせています（[standards.md](standards.md)）。
スタンドアロンアプリは自前のオーディオ処理に置き換え、入力デバイスの選択画面を追加しました（[#2](https://github.com/My-MC/shirabe/issues/2)）。
PLR（最大トゥルーピークと Integrated ラウドネスの差）を表示できます。
音声ファイル（WAV / FLAC）を再生しながらの測定は実装し、Linux で確認しました。

- トゥルーピーク（ITU-R BS.1770 Annex 2 を参照）
- ラウドネス：Momentary、Short-term、Integrated、LRA（ITU-R BS.1770、EBU Tech 3341 / 3342）と PLR（EBU R 128 s2）
- 目標値プリセット：ARIB TR-B32、EBU R128、ATSC A/85、配信向け
- VU（IEC 60268-17）、PPM（IEC 60268-10）
- VU のバー／針表示の切り替え（実装済み）
- ホストの再生開始に連動した Integrated のリセット
- スタンドアロン専用 UI：オーディオデバイスの選択画面、音声ファイルを再生しながらの測定（実装済み）
- スタンドアロンのオーディオ処理を自前の実装に置き換え、デバイスのサンプルレートと任意のバッファサイズに対応（[#2](https://github.com/My-MC/shirabe/issues/2)）

完了条件は次のとおりです。

1. EBU Tech 3341 / 3342 の適合性テスト信号を使った自動テストがすべて許容範囲内に入る。
2. スタンドアロンアプリで、入力デバイスの選択と音声ファイルの再生測定ができる（2026-11-26 に Linux で確認）。

## フェーズ 2：ステレオ解析

- リサージュ（実装済み：M/S 表示、±1 を 0 dBFS とする固定スケールと自動ゲイン、残光、モノラルの明示）
- 相関メーター、左右バランスメーター（実装済み：固定 400 ms 窓）
- ベクタースコープ（実装済み：L を横軸、R を縦軸とする X/Y 表示。リサージュと同じサンプルの別表示で、残光と自動ゲインを共用）
- 波形データを UI に渡すロックフリーのリングバッファ（実装済み。リサージュとベクタースコープで共用）

## フェーズ 3：レイアウトとプリセット

- タイル分割のレイアウトエンジン（実装済み：7 種類のタイルと、Standard / Stereo / History / Spectrum の 4 つのプリセット。タイルを利用者が編集する画面は未実装）
- メーターの登録方式（表示側は実装済み：`TileId` と描画関数の対応表をすべてのタイルで共用。計測側の `MeterProcessor` は未着手）
- レイアウトとテーマの保存・読み込み（実装済み：スタンドアロン専用の外観プリセットファイル。バージョン 1 で、レイアウト名とテーマ色を入出力します。任意のタイル構成とプラグインでの入出力は未着手）
- 用途別の初期プリセット（未着手。放送、マスタリング、リスニング、ミックスなどの名前は、確認できる資料がないためまだ使いません）
- 日本語 / 英語の表示切り替え（実装済み：既定は英語。共有エディターとスタンドアロン画面。表示専用の `ui_lang` で保存）

最初の版では、既存の配置を Standard、ステレオ表示を大きく取る配置を Stereo として選べるようにしました。
切り替えは画面上部の「Layout」で行い、計測値とオーディオの経路は変わりません。

表示側の登録表は、タイルの識別子 `TileId`（`peak`、`level`、`loudness`、`readout`、`scope`）と描画関数の対応です。
エディターはこの表だけを使ってタイルを描くため、プリセットが置いたタイルに描画関数が無いまま表示だけ欠けることがありません。
識別子は将来の任意タイル構成のキーにする予定で、名前を変えたり再利用したりしません。
計測側の `MeterProcessor` を今は導入していない理由は [design.md](design.md) に書いています。

外観プリセットファイルは、スタンドアロンアプリの「Appearance」から明示的に入出力します。
バージョン 1 のファイルには、レイアウト名とテーマ色だけを保存します。
VU / PPM バーでは通常域と超過域の色を指定でき、切り替え位置は組み込みの目盛りに従います。
ファイル入出力中も画面と計測を止めず、既存ファイルを置き換える場合は対象を明示して確認します。
読み込みは全体を検証してから適用し、目標値、オシレーター、入力、計測値、既存のパラメーター ID と保存キーは変更しません。
任意のタイル構成とプラグインでの入出力は、まだ実装していません。

画面の表示言語は、ヘッダーの「EN / JA」から日本語と英語を切り替えられます。
既定は英語で、切り替えは表示だけに働き、計測値、オーディオの経路、目標値は変わりません。
共有エディター（プラグインとスタンドアロンの両方）と、スタンドアロンアプリのデバイス・再生・外観画面に適用します。
単位（`dBFS`、`dBTP`、`LUFS`、`LU`、`dB` など）と規格の呼び名（EBU、ARIB TR-B32、ATSC A/85、PPM など）、パラメーター ID は変えません。
OS が返すデバイス名、外観ファイルの詳細なエラー文、リサージュの `CLIP` / `FIXED` / `AUTO` / `HOLD` は英語のままです。
日本語の表示には OS の日本語フォントを使い、フォントを同梱しません。
フォントが見つからない環境では日本語を選べなくし、英語で表示します。
選択した言語は、自動化できない表示専用の `ui_lang` として保存します。
既存のプロジェクトと `standalone.json` に `ui_lang` がない場合は英語で起動します。
外観プリセットファイルの形式は変えず、入出力で言語を変更しません。

## フェーズ 4：記録

- ラウドネスの時間変化グラフ（実装済み：Momentary と Short-term を 100 ms ごとに 3 分間記録し、目標値と許容範囲を重ねて表示します。専用のタイル `history` とレイアウトプリセット History で表示します）
- 測定結果の CSV / JSON 出力（実装済み：スタンドアロンアプリ。「Export measurement」から、その時点の概要と記録済みの M / S の履歴を書き出します）

グラフは表示専用で、計測値とオーディオの経路を変えません。
記録は 100 ms ごとの固定間隔で、リングバッファは 1800 点（3 分）です。
測定の Pause 中は記録を止めて表示を凍結し、Reset、入力の切り替え、サンプルレートの変更で消去します。
保存や自動化の対象にはせず、計測の履歴そのものは保存しません。
表示の詳細は [design.md](design.md) に書いています。

測定結果の書き出しは、押した時点の値を画面側でまとめてから、専用のワーカーがファイルに書きます。
書き出し中も計測は止まらず、ファイルには押した瞬間の概要と、その時点までの履歴が残ります。
概要には Integrated、LRA、PLR、M / S の最大値、チャンネルごとの最大トゥルーピーク、番組時間、目標値、サンプルレート、チャンネル構成、入力の説明、アプリのバージョン、UTC の書き出し時刻を含めます。
数値は小数点に `.` を使い、測定できない値は JSON では `null`、CSV では空欄にします。
同じ内容を CSV とバージョン付きの JSON（`shirabe-measurement/1`）で書けます。
入力が音声ファイルのときは、既定ではファイル名だけを書き、利用者が選んだ場合だけフルパスを含めます。
既存ファイルの置き換えは外観プリセットと同じく、対象を確認してから行います。
プラグインからの書き出しは、ホストの画面にファイル選択を出す方法が未確定のため、未着手です。

## フェーズ 5：制作向け機能

- FFT スペクトラム、1/3 オクターブ RTA（実装済み：タイル `spectrum` とレイアウトプリセット Spectrum。16384 点の FFT、周期 Hann 窓、125 ms の指数平均、0〜-90 dBFS、20 Hz〜20 kHz の対数軸）
- サイドチェーン入力によるリファレンス音源との比較
- wgpu による GPU 描画
- インストーラー、macOS の署名と公証

スペクトラムは表示専用で、計測値とオーディオの経路を変えません。
オーディオスレッドは L / R のモノラル合計を固定長のリングバッファに書くだけで、FFT は UI スレッドで行います。
1/3 オクターブは FFT ビンをまとめた表示用の集計で、IEC 61260-1 のフィルタークラスには準拠しません（[standards.md](standards.md)）。
表示の詳細と分解能の制限は [design.md](design.md) に書いています。
