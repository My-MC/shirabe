## フェーズ 0：基盤

- Cargo ワークスペース（`shirabe-dsp`、`shirabe-ui`、`shirabe-plugin`、`xtask`）
- サンプルピークメーター（モノラル / ステレオ / 5.1）
- テストオシレーター
- VST3、CLAP、スタンドアロンアプリのビルド
- GitHub Actions（fmt、clippy、テスト、Windows / Linux のバンドル、pluginval による VST3 検証）

完了条件は次のとおりです。

1. CI がすべて成功し、Windows 向けの成果物が生成される。
2. Windows のホストアプリケーションで VST3 を読み込み、音がそのまま通り、メーターが動く。
3. スタンドアロンアプリが起動し、テストオシレーターでメーターが動く。

## フェーズ 1：規格準拠の基本メーター

- トゥルーピーク（ITU-R BS.1770 Annex 2）
- ラウドネス：Momentary、Short-term、Integrated、LRA、PLR（ITU-R BS.1770、EBU Tech 3341 / 3342）
- 目標値プリセット：ARIB TR-B32、EBU R128、ATSC A/85、配信向け
- VU（IEC 60268-17）、PPM（IEC 60268-10）
- ホストの再生開始に連動した Integrated のリセット
- スタンドアロン専用 UI：オーディオデバイスの選択画面、音声ファイルを再生しながらの測定

完了条件は次のとおりです。

1. EBU Tech 3341 / 3342 の適合性テスト信号を使った自動テストがすべて許容範囲内に入る。
2. スタンドアロンアプリで、入力デバイスの選択と音声ファイルの再生測定ができる。

## フェーズ 2：ステレオ解析

- リサージュ（残光表示、自動ゲイン）
- 相関メーター、バランスメーター
- ベクタースコープ
- 波形データを UI に渡すロックフリーのリングバッファ

## フェーズ 3：レイアウトとプリセット

- タイル分割のレイアウトエンジン
- `MeterProcessor` / `MeterView` によるメーターの登録方式
- レイアウトとテーマの保存・読み込み（スキーマのバージョン付き）
- 用途別の初期プリセット（放送、マスタリング、リスニング、ミックス）
- 日本語 / 英語の表示切り替え

## フェーズ 4：サラウンドと記録

- 5.1 / 7.1 のサラウンド表示
- ラウドネスの時間変化グラフ
- 測定結果の CSV / JSON 出力

## フェーズ 5：制作向け機能

- FFT スペクトラム、1/3 オクターブ RTA
- サイドチェーン入力によるリファレンス音源との比較
- wgpu による GPU 描画
- インストーラー、macOS の署名と公証
