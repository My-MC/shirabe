# 設計

Shirabe Meter Suite の構成、スレッド設計、メーターの仕様、互換性の方針を説明します。

[ドキュメント一覧に戻る](README.md) ・ [README](../README.md)

## 基本方針

- 音は加工しません。テストオシレーターを有効にしたとき以外は、入力をそのまま出力します。
- レイテンシーは 0 です。先読みが必要な処理は、計測側の内部遅延として扱い、出力には影響させません。
- オーディオスレッドでは、メモリ確保・ロック・ファイル入出力を行いません。
- 計測値は規格に基づいて検証できるようにします。各メーターには準拠する規格と自動テストを対応させます。
- プラグイン、スタンドアロンアプリ、将来のツール（ファイルの一括測定など）で、同じ計測コードと同じ UI 部品を共有します。

## クレート構成

| クレート | 役割 | 依存してよいもの | ライセンス |
|---|---|---|---|
| `shirabe-dsp` | 計測処理（ピーク、VU、ラウドネスなど）とチャンネル構成 | 標準ライブラリのみ（数値計算用クレートは可） | MIT OR Apache-2.0 |
| `shirabe-ui` | メーターの描画部品、目盛り、テーマ | `egui`（`nih_plug_egui` 経由） | GPL-3.0-or-later |
| `shirabe-plugin` | プラグイン本体、エディター、スタンドアロンアプリ | 上記すべてと `nih_plug` | GPL-3.0-or-later |
| `xtask` | VST3 / CLAP のバンドル作成 | `nih_plug_xtask` | GPL-3.0-or-later |

`shirabe-dsp` はプラグインフレームワークにも GUI にも依存させません。

これにより、計測処理を `cargo test` だけで検証でき、他のプロジェクトからも再利用できます。

## スレッドとデータの流れ

```text
[オーディオスレッド]                         [UI スレッド]
入力 ──────────────→ 出力（そのまま）
  │
  ├─ shirabe-dsp の各メーター
  │    （状態はオーディオスレッドだけが持つ）
  │
  └─ 公開 ──→ SharedMeters（atomic） ──→ エディターが毎フレーム読む
                  ↑
                  └── リセット要求（atomic フラグ）←── UI 操作
```

- 数値の読み出しは `AtomicF32` で行います。値ごとに独立しているため、ロックは不要です。
- 波形そのものが必要なメーター（リサージュ、ベクタースコープ、スペクトラム）は、ロックフリーのリングバッファでサンプル列を UI に渡します（フェーズ 2 で導入）。
- UI からオーディオスレッドへの要求（最大値のリセットなど）は、atomic フラグで伝えます。
- デバッグビルドでは `assert_process_allocs` により、オーディオスレッドでのメモリ確保を検出すると停止します。

## メーターの仕様

| メーター | 準拠する規格・仕様 | 主な設定 | 実装フェーズ |
|---|---|---|---|
| サンプルピーク | デジタル番組メーターの一般的な動特性（20 dB / 1.7 s で降下） | ピークホールド時間、降下速度 | 0（実装済み） |
| トゥルーピーク | ITU-R BS.1770 Annex 2（4 倍以上のオーバーサンプリング） | オーバーサンプリング倍率 | 1 |
| ラウドネス | ITU-R BS.1770、EBU Tech 3341 / 3342 | Momentary、Short-term、Integrated、LRA、PLR | 1 |
| ラウドネス目標値 | ARIB TR-B32、EBU R128、ATSC A/85、配信向け | 目標値と許容範囲のプリセット | 1 |
| VU | IEC 60268-17 | 基準レベル（0 VU = -18 / -20 dBFS など） | 1 |
| PPM | IEC 60268-10（Type I / II） | 種類の選択 | 1 |
| リサージュ | L/R を 45° 回転した M/S 表示 | 残光、自動ゲイン、点と線の切り替え | 2 |
| 相関・バランス | -1〜+1 の相関、L/R バランス | 積分時間 | 2 |
| ベクタースコープ | 振幅と角度の極座標ヒストグラム | 減衰時間 | 2 |
| サラウンド | ITU-R BS.1770 のチャンネル重み付け | 5.1 / 7.1 の表示 | 4 |
| スペクトラム | FFT、1/3 オクターブ | 窓関数、平均化 | 5 |

### チャンネル構成

チャンネルは「役割」（L、R、C、LFE、Ls、Rs など）で扱います。

ラウドネスの重み付け（サラウンドは +1.5 dB、LFE は除外）は、役割から自動で決まります。

| 構成 | チャンネル順 | 状態 |
|---|---|---|
| Mono | M | 対応済み |
| Stereo | L、R | 対応済み |
| 5.1 | L、R、C、LFE、Ls、Rs | 対応済み |
| 7.1 | — | 未対応（ホストへ通知するスピーカー配置の調整が必要） |

## UI の構成

- 画面をタイルに分割し、各タイルにメーターを 1 つ割り当てます（フェーズ 3）。
- 分割の構造は木構造のデータとして持ち、JSON で保存します。
- テーマ（色、色分けの区切り、セグメントの形）はデータとして持ち、将来はファイルから読み込めるようにします。
- メーターの描画部品は値を受け取って描くだけにし、音声処理の状態には触れません。

### 新しいメーターを追加するときの形

計測側と表示側をそれぞれ 1 つずつ追加し、一覧に登録するだけで追加できる構造を目指します（フェーズ 3 で導入）。

```rust
/// 計測側（オーディオスレッド）
pub trait MeterProcessor: Send {
    fn prepare(&mut self, sample_rate: f32, layout: ChannelLayout);
    fn process(&mut self, block: &[&[f32]]);
    fn reset(&mut self);
}

/// 表示側（UI スレッド）
pub trait MeterView {
    fn draw(&mut self, ui: &mut egui::Ui, theme: &Theme);
}
```

## 互換性の方針

| 対象 | 方針 |
|---|---|
| パラメーター ID（`#[id = ...]`） | 一度公開したら変更・再利用しません。保存済みのプロジェクトが壊れるためです |
| 保存キー（`#[persist = ...]`） | 同上。中身の形式を変えるときはバージョン番号を持たせ、古い形式から変換します |
| VST3 クラス ID、CLAP ID | 変更しません |
| レイアウト・テーマのファイル | スキーマのバージョンを持たせ、古い形式を読み込めるようにします |

現在のパラメーターは次のとおりです。

| ID | 名前 | 範囲 | 初期値 |
|---|---|---|---|
| `osc_on` | Test Oscillator | オン / オフ | オフ |
| `osc_lvl` | Oscillator Level | -60〜0 dBFS | -18 dBFS |
| `osc_frq` | Oscillator Frequency | 20 Hz〜20 kHz | 1 kHz |

## ライセンスについて

- VST3 の出力に使っているバインディングが GPLv3 のため、プラグイン本体は GPL-3.0-or-later です。
- `shirabe-dsp` は他のプロジェクトでも使えるよう、MIT OR Apache-2.0 とします。そのため `shirabe-dsp` には GPL のコードを含めません。
- プラグインで処理・計測した音声や楽曲には GPL は適用されません。
