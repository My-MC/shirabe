# 設計

Shirabe Meter Suite の構成、スレッド設計、メーターの仕様、互換性の方針を説明します。

[ドキュメント一覧に戻る](README.md) ・ [README](../README.md)

## 基本方針

- 音は加工しません。テストオシレーターを有効にしたとき以外は、入力をそのまま出力します。
- レイテンシーは 0 です。先読みが必要な処理は、計測側の内部遅延として扱い、出力には影響させません。
- オーディオスレッドでは、メモリ確保・ロック・ファイル入出力を行いません。
- 計測値は規格に基づいて検証できるようにします。各メーターには準拠する規格と自動テストを対応させます。
- プラグイン、スタンドアロンアプリ、将来のツール（ファイルの一括測定など）で、同じ計測コードと同じ UI 部品を共有します。

## クレート構成

| クレート | 役割 | 依存してよいもの | ライセンス |
|---|---|---|---|
| `shirabe-dsp` | 計測処理（ピーク、VU、ラウドネスなど）とチャンネル構成 | 標準ライブラリのみ（数値計算用クレートは可） | MIT OR Apache-2.0 |
| `shirabe-ui` | メーターの描画部品、目盛り、テーマ | `egui`（`nih_plug_egui` 経由）、`shirabe-dsp`（座標変換のみ） | GPL-3.0-or-later |
| `shirabe-plugin` | プラグイン本体、計測エンジン（`MeterEngine`）、エディター | 上記すべてと `nih_plug` | GPL-3.0-or-later |
| `shirabe-app` | スタンドアロンアプリ（デバイス選択、設定の保存） | 上記すべてと `cpal`、`eframe` | GPL-3.0-or-later |
| `xtask` | VST3 / CLAP のバンドル作成 | `nih_plug_xtask` | GPL-3.0-or-later |

`shirabe-dsp` はプラグインフレームワークにも GUI にも依存させません。

スタンドアロンアプリは、プラグインと同じ `MeterEngine` とエディターの描画関数（`editor::draw`）を使います。
音声入力は `cpal` で直接開き、デバイスのサンプルレートと任意のバッファサイズをそのまま受け付けます。
再生中の音は、Windows では WASAPI ループバック（`cpal`）、Linux では PulseAudio のモニター（`libpulse` を実行時に読み込み）、macOS 14.2 以降では Core Audio のプロセスタップ（実行時に関数を探す）で取り込みます。
実行時に読み込むので、これらがない環境でもアプリは起動し、その項目だけが表示されません。
パラメーターは、ホストの代わりにアプリ側の `GuiContext` 実装が直接書き換えます（nih-plug のフォークで `ParamPtr::set_normalized_value` を公開）。

これにより、計測処理を `cargo test` だけで検証でき、他のプロジェクトからも再利用できます。

## 音声ファイルの再生（スタンドアロン）

スタンドアロンアプリは、WAV と FLAC のファイルを再生しながら測定できます。
デコードしたサンプルをそのままメーターに渡すため、表示される値はファイルに記録されたサンプルそのものの値です。
スピーカーの音量や、OS のミキサーを通ったあとの信号は測りません。

```text
[デコードスレッド]                                   [オーディオコールバック]
ファイル → デコード（f32）→ メーター（ファイルのレート）
                              ↓
                       ステレオへ変換（1 ch は L/R に複製、3 ch 以上は 1-2 ch のみ）
                              ↓
                       サンプルレート変換（必要なときだけ）
                              ↓
                       リングバッファ（100 ms、ロックフリー） ──→ デバイスへ書き込み
```

- メーターは常にファイルのサンプルレートで動きます（画面の「44.1 kHz」はファイルの値です）。
  デバイスが 48 kHz でも、メーターの値は変わりません。
- サンプルレート変換は、メーターのあと、出力の直前だけに行います。
  そのため、変換の有無で測定値は変わりません。
- デコードスレッドとコールバックの間は、固定長のリングバッファ（100 ms）で受け渡します。
  コールバックはメモリ確保もロックも待ち合わせも行わず、間に合わない分は無音で埋めます。
- 再生位置は、デバイスが実際に取り出したフレーム数から求めます。
- 一時停止中と再生終了後は、無音をメーターに流して値を自然に下げます。
- 出力デバイスは、ファイルと同じサンプルレート・2 ch で開けるものを優先します。
  開けない場合はデバイスの既定のレートで開き、変換します。
- Linux の ALSA では、出力のバッファを 50 ms 相当に固定します。
  cpal はこの値を 4 つの周期に分けて開くため、ALSA が受け付けるよう 4 の倍数に丸めます
  （44.1 kHz は 2204 フレーム、48 kHz は 2400 フレーム）。

### 対応形式と制限

| 項目 | 内容 |
|---|---|
| WAV | PCM 8 / 16 / 24 / 32 bit、IEEE float 32 bit |
| FLAC | 8〜32 bit（可逆） |
| その他の形式 | 未対応（MP3、AAC、Ogg など）。拡張子ではなく先頭のバイトで判定します |
| チャンネル | 1 ch は L/R に複製、2 ch はそのまま、3 ch 以上は 1-2 ch だけを再生・測定します |
| シーク、ループ | 未対応（「最初から」で先頭に戻ります） |
| ファイルの選択 | パスの入力欄とドラッグ＆ドロップのみ（OS のファイル選択ダイアログは未対応） |
| クロックのずれ補正 | 未対応（デバイスとのわずかな速度差は、100 ms のバッファで吸収します） |
| サンプルレート変換の品質 | 監視用です。マスタリング用の変換ではありません（下記） |

### サンプルレート変換

サンプルレート変換は、窓関数付き sinc のポリフェーズ方式です。
比は整数の比に約分して扱うため、44.1 kHz と 48 kHz の間でずれが蓄積しません。
タップ数は 1 相あたり 96、遮断周波数は低いほうのナイキスト周波数の 90 % です。
通過帯域のリップルと阻止域の減衰は自動テストで確認しています（[testing.md](testing.md)）。

## スレッドとデータの流れ

```text
[オーディオスレッド]                         [UI スレッド]
入力 ──────────────→ 出力（そのまま）
  │
  ├─ shirabe-dsp の各メーター
  │    （状態はオーディオスレッドだけが持つ）
  │
  └─ 公開 ──→ SharedMeters（atomic） ──→ エディターが毎フレーム読む
                  ↑
                  └── リセット要求（atomic フラグ）←── UI 操作
```

- 数値の読み出しは `AtomicF32` で行います。値ごとに独立しているため、ロックは不要です。
- リサージュとベクタースコープは、固定長のロックフリーリングバッファで渡した同じステレオのフレームを、別の座標で表示します。
- UI からオーディオスレッドへの要求（最大値のリセットなど）は、atomic フラグで伝えます。
- デバッグビルドでは `assert_process_allocs` により、オーディオスレッドでのメモリ確保を検出すると停止します。

## メーターの仕様

| メーター | 準拠する規格・仕様 | 主な設定 | 実装フェーズ |
|---|---|---|---|
| サンプルピーク | デジタル番組メーターの一般的な動特性（20 dB / 1.7 s で降下） | ピークホールド時間、降下速度 | 0（実装済み） |
| トゥルーピーク | ITU-R BS.1770 Annex 2（96 kHz 未満は 4 倍、192 kHz 未満は 2 倍のオーバーサンプリング） | なし（サンプルレートで自動決定） | 1（実装済み） |
| ラウドネス | ITU-R BS.1770-5、EBU Tech 3341 / 3342 | M、S、I、LRA、EBU +9 / +18 目盛り、LUFS / LU 表示、I と LRA の一時停止（実装済み）、PLR（番組の最大トゥルーピークと Integrated の差） | 1 |
| ラウドネス目標値 | ARIB TR-B32、EBU R 128、ATSC A/85、Spotify、Apple Podcasts、Custom | 目標値と許容範囲のプリセット | 1（実装済み） |
| VU | IEC 60268-17（300 ms で 99 %、オーバーシュート 1〜1.5 %） | 基準レベル（0 VU = -24〜-8 dBFS、初期値 -18 dBFS） | 1（実装済み） |
| PPM | IEC 60268-10、EBU Tech 3205（Type I：0 dB = -9 dBFS、Type II：TEST / 4 = -18 dBFS） | Type I、EBU 目盛り（IIb）、BBC 目盛り（IIa）、IEEE 目盛り（IEEE Std 152-1991） | 1（実装済み） |
| リサージュ | L/R を 45° 回転した M/S 表示（縦が中点、横が側成分） | ±1 を 0 dBFS とする固定スケールと自動ゲインの切り替え、残光、モノラルの明示 | 2（基本表示、残光、自動ゲインを実装済み） |
| 相関・バランス | -1〜+1 の相関、L/R バランス | 固定 400 ms 窓 | 2（実装済み） |
| ベクタースコープ | 特定の規格に基づかない表示（L を横軸、R を縦軸とする X/Y 表示） | リサージュと同じ残光と自動ゲイン | 2（実装済み） |
| サラウンド | ITU-R BS.1770 のチャンネル重み付け | 5.1 / 7.1 の表示 | 将来 |
| スペクトラム | FFT、1/3 オクターブ | 窓関数、平均化 | 5 |

### ステレオ相関と左右バランス

画面上部の `Corr` と `Bal` は、直近 400 ms のステレオ信号を測ります。
相関は左右の積の和を左右のエネルギーの幾何平均で割った値で、同相は +1、逆相は -1、直交する信号は 0 です。
直流成分は除去しません。
バランスは左右のエネルギー比から求め、強い側とその差を dB で表示します。
モノラル、無音、または最初の測定窓が揃っていない間は `--` と表示します。
片側のみの場合は `L only` または `R only` と表示し、相関は `--` と表示します。

### リサージュ表示

ステレオの L/R を 45° 回転した M/S 座標で表示します。
縦軸が中点成分 M = (L + R) / 2、横軸が側成分 S = (L − R) / 2 です。
そのため、位相のそろったモノラル信号は縦の直線、逆相は横の直線、90° の位相差は円になります。
M/S 表示と L/R 表示は同じサンプルの別の見方で、新しい計測を追加するものではありません。

| 項目 | 内容 |
|---|---|
| スケール | 固定では各軸の ±1 が 0 dBFS です。フルスケールのモノラルは上端、90° のフルスケール正弦波は半径 70.7 % の円になります |
| 自動ゲイン | 信号のピークに合わせて表示だけを最大 +20 dB 拡大します。適用中の値はタイトルの右に `AUTO +12.4 dB` のように表示します。入力が 0 dBFS を超える場合は固定スケールと同じくクリップとして扱います |
| 残光 | 直近 0.3 秒の点を、経過時間に比例して薄く描きます。新しいサンプルが届かないときは、最新の軌跡を残し、残光だけが消えます |
| クリップ | ゲイン適用前の M または S が ±1 を超えたときだけ `CLIP` を表示します。表示上の拡大によって枠を超えた点は枠上に描きますが、`CLIP` にはしません。L / R のピーク超過はピークメーターで確認します |
| 表示区間 | 直近 2048 フレームです（48 kHz で約 43 ms） |
| モノラル入力 | 図は描かず、`MONO` と `no stereo content` を表示します。L/R を複製すると、完全に相関したステレオのように見えてしまうためです |
| 未実装 | トリガーによる位相の固定（[ロードマップ](roadmap.md)） |

残光は初期状態でオン、自動ゲインは初期状態でオフ（固定スケール）です。
「Level」の行の「L/R」でベクタースコープに切り替え、「Trail」と「Auto」で残光と自動ゲインを切り替えます。
サンプル列は、4096 フレーム固定のロックフリーリングバッファで UI に渡します。
あふれた古いフレームから捨てるため、UI が遅れてもオーディオスレッドは待ちません。
オーディオスレッドは書き込むだけで、ロックもメモリ確保もしません。
残光は、UI が前回読んだ位置から新しく届いたフレームだけを履歴に追加します。
そのため、一時停止中に同じ軌跡を繰り返し重ねることはありません。
無音サンプルが届く実装では、最新の軌跡も原点に戻ります。
残光中の点には、取り込んだ時点の表示ゲインを使います。
入力の切り替え、モノラルへの変更、リングバッファのクリアでは履歴と自動ゲインを初期化します。
自動ゲインは表示専用で、ピーク、ラウドネスなどの計測値には触れません。
ピーク包絡は 2 秒で解放し、ゲインは下げるとき 0.15 秒、上げるとき 0.8 秒で目標値に近づけます。
入力が -60 dBFS 未満のときはゲインを上げず、最後の値を保持して `HOLD` と表示します。
無音時にゲインが上がり続けて、実際より大きな信号に見えることを避けるためです。
残光の履歴は 16384 点まで保持します。
サンプルレートが高いときは、時間より点数の上限で先に古い点が消えます。
メーター領域の高さが 333 論理ピクセルに満たないときは、数値のラウドネス表示を優先し、リサージュを隠します。
小さいウィンドウでリサージュを見るには、ウィンドウを縦に広げます。

### ベクタースコープ表示

「Level」の行にある「L/R」をオンにすると、同じステレオのフレームを L と R の座標で表示します。
横軸が L（右が正）、縦軸が R（上が正）で、図の右端に `L`、上端に `R` のラベルを表示します。
これはリサージュと同じサンプル列の別の表示であり、相関やバランスなどの計測値を変えるものではありません。
オーディオの処理も通り道も変わりません。

| 項目 | 内容 |
|---|---|
| スケール | 固定では各軸の ±1 が 0 dBFS です。L と R が同じ大きさなら 45° の直線、逆相なら右下がりの直線になります |
| 自動ゲイン | リサージュと同じ仕組みを共用します。表示だけを最大 +20 dB 拡大し、適用中の値はタイトルの右に表示します |
| 残光 | リサージュと同じ 0.3 秒の履歴を共用します |
| クリップ | L または R が ±1 を超えたときだけ `CLIP` を表示します。M/S 表示の判定（M または S が ±1 を超えたとき）とは軸が違うため、同じ信号でも表示が異なることがあります |
| モノラル入力 | リサージュと同じく図は描かず、`MONO` と `no stereo content` を表示します。L/R を複製すると、完全に相関したステレオのように見えてしまうためです |
| 表示の切り替え | 表示履歴と自動ゲインを初期化し、切り替え後の座標でリングバッファの最新フレームから描き直します。計測値とリングバッファの内容は変わりません |

表示の切り替えは、表示専用のパラメーター `scp_lr` で保存します。
自動化には対応せず、初期値はオフ（M/S 表示）です。
既存のパラメーター ID と初期値は変えていません。
軸の向きと目盛りは表示上の取り決めで、準拠する規格を確認したものではありません（[standards.md](standards.md)）。

### チャンネル構成

チャンネルは「役割」（L、R、C、LFE、Ls、Rs など）で扱います。

ラウドネスの重み付け（サラウンドは +1.5 dB、LFE は除外）は、役割から自動で決まります。

各項目がどの資料のどの要件に従うかは、[standards.md](standards.md) にまとめています。

## 計測処理の実装

各メーターの実装方法は次のとおりです。

| メーター | 実装 |
|---|---|
| ラウドネス | K 特性フィルターは規格のアナログ原型から係数を求め、48 kHz では規格の係数表と一致します。100 ms を割り切る 2.5 ms 以下の区間ごとのエネルギーをリングバッファに保持し、M と S の窓を細かく移動させます。ゲーティングブロック（400 ms、100 ms 間隔）は 0.01 LU 刻みのヒストグラムに集計します。メモリは初期化時にのみ確保します。 |
| トゥルーピーク | カイザー窓の sinc によるポリフェーズ補間（1 位相 32 タップ）で、サンプル間のピークを推定します。 |
| VU | 全波整流した信号を 2 次系（減衰比 0.8007）で平滑化し、針の動きを再現します。固有振動数は初期化時に 300 ms の立ち上がり条件から求めます。 |
| PPM | 2 段の充電回路と dB 一定速度の降下で準ピーク値を求めます。充電の速さは、Type I は IEC 60268-10 のバースト応答に、Type II は EBU Tech 3205 表 2 に合わせて決め、定常の 5 kHz で振幅どおりの値になるよう正規化します。 |

オーディオスレッドでは、処理中だけ非正規化数を 0 として扱う設定（FTZ / DAZ）を有効にし、終了時に元へ戻します。

| 構成 | チャンネル順 | 状態 |
|---|---|---|
| Mono | M | 対応済み |
| Stereo | L、R | 対応済み |
| 5.1 | L、R、C、LFE、Ls、Rs | 将来対応（計測ライブラリにチャンネルの役割だけ定義済み） |
| 7.1 | — | 将来対応（ホストへ通知するスピーカー配置の調整が必要） |

サラウンドは、5.1 の再生環境と検証用の音源が用意できてから対応します。
現在のプラグインとスタンドアロンアプリが受け付けるのは、モノラルとステレオだけです。

なお、ホストによっては、プラグインに渡す前に出力デバイスのチャンネル数へダウンミックスします。
サラウンドに対応するときは、この点も含めて実機で確認します。

## UI の構成

- 画面をタイルに分割し、各タイルにメーターを 1 つ割り当てます。
- タイルは Peak（サンプルピークとトゥルーピーク）、Level（VU / PPM）、Loudness（M / S のバー）、Readout（数値のラウドネス）、Scope（リサージュ / L/R ベクタースコープ）の 5 種類です。
- 各タイルの位置は `shirabe-ui` の `layout` モジュールが決め、描画側は渡された矩形に描くだけです。計測値には触れません。
- 各タイルの描画関数は `shirabe-ui` の `view` モジュールの対応表に登録し、エディターはその表だけを使って描きます（下記）。
- プリセットは Standard と Stereo の 2 つです。
- Standard は従来の配置で、Peak、Level、Loudness の 3 列と、右列の Readout（上）と Scope（下）からなります。
- Stereo はステレオ表示を優先する配置で、Peak と Level を左に縦積みし、中央に高さいっぱいの Scope、右に Loudness（上）と Readout（下）を置きます。
- 切り替えは画面上部の「Layout」で行い、表示専用のパラメーター `lay_preset` で保存します。
- 切り替えても計測、出力、オートメーションの値は変わりません。
- ウィンドウが低いときは、数値のラウドネス表示を優先します。Standard では Scope を隠し、Stereo では Loudness のバーを先に隠します。
- スタンドアロンアプリでは、レイアウトとテーマ色をバージョン付きの外観プリセットファイルに保存し、読み込めます（下記）。
- タイルを利用者が自由に組み替える画面、プラグインでの外観ファイルの入出力、表示言語の切り替えは未実装です（[ロードマップ](roadmap.md)）。
- テーマ（色、色分けの区切り、セグメントの形）はデータとして持ち、外観プリセットファイルでは色だけを保存します。
- メーターの描画部品は値を受け取って描くだけにし、音声処理の状態には触れません。

### タイルの ID と描画の登録

タイルは `TileId` の 5 種類で、それぞれに保存用の識別子を持たせています。

| 識別子 | タイル | 内容 |
|---|---|---|
| `peak` | `TileId::Peak` | サンプルピークとトゥルーピーク |
| `level` | `TileId::Level` | VU または PPM |
| `loudness` | `TileId::Loudness` | M / S のラウドネスバー |
| `readout` | `TileId::Readout` | 数値のラウドネス表示 |
| `scope` | `TileId::Scope` | リサージュまたは L/R ベクタースコープ |

`shirabe-ui` の `view` モジュールが、タイルと描画関数の対応表（`MeterViewRegistry`）を持ちます。
エディターは配置（`layout`）と対応表を突き合わせ、置かれたタイルだけを表の順に 1 回ずつ描きます。
表はフレームごとに作る固定長の配列で、メモリ確保も仮想呼び出しも伴いません。
`TileId::ALL` から表を作り、描画関数の選択はすべての種類を網羅する `match` にしているため、タイルを増やすと描画関数を書くまでコンパイルが通りません。
識別子が重複した表は `MeterViewRegistry::new` が拒否します。

自動テストでは次を確認しています。

| 確認すること | 内容 |
|---|---|
| 識別子の一意性と固定 | 5 つの名前が重複せず、`peak` などの文字列が変わらないこと |
| 引き当ての完全性 | 2 つのプリセットが既定サイズと最小サイズで置くすべてのタイルに、描画関数が 1 つずつあること |
| 配置の非回帰 | プリセットが置くタイルとその順序が、プリセット導入時と同じであること |
| 描画順と矩形 | 表の順（Peak、Level、Loudness、Readout、Scope）で、配置された矩形にだけ描くこと |

描画順を表の順に固定しているのは、見出しが自分の矩形から少しはみ出すタイルがあり、後のタイルが上に重なるためです。
そのため、プリセットがタイルを置く順（Stereo では Scope が 3 番目）と描画の順は一致しません。

### 外観プリセットファイル（スタンドアロン）

レイアウト名とテーマ色は、スタンドアロンアプリの「Appearance」から 1 つの JSON ファイルに保存し、読み込めます。
「Export」と「Import」を押したときだけ動作し、起動時や測定中に自動では読み書きしません。
ファイルのパスは画面で指定し、既定値は設定ディレクトリの `appearance.json` です。
プラグインにはこの画面がないため、プラグインの表示は変わりません。

| フィールド | 内容 |
|---|---|
| `format` | `shirabe-appearance` 固定 |
| `version` | スキーマのバージョン。現在は `1` |
| `layout` | `standard` または `stereo`（`lay_preset` の保存 ID と同じ） |
| `theme` | 背景、パネル、文字、保持線、目標内・超過の色と、Peak / VU の色分け |

- 色は `#rrggbb` で書きます。透明度と色名は受け付けません。
- 色分けは `from_db` の昇順で並べ、最初の区切りだけ `from_db` を省略できます（下限なし）。
- 色分けは 1 つの並びにつき 32 個まで受け付けます。
- セグメントの高さと間隔はファイルに含めず、現在の組み込み値を使います。

読み込みは、ファイル全体を 64 KiB まで読み、形式、バージョン、レイアウト名、すべての色を検証してから適用します。
検証に失敗したときは、テーマ、パラメーター、保存済みの設定のどれも変更しません。
適用するのは `lay_preset` とテーマ色だけです。
目標値、テストオシレーター、入力デバイス、測定値、既存のパラメーター ID と保存キーは変更しません。
レイアウトの切り替えは測定を止めず、Integrated などの値を初期化しません。

エクスポートは、既存のファイルを確認なしに置き換えません。
同名のファイルがあるときは「Overwrite」と「Cancel」を表示し、「Overwrite」を押したときだけ、警告したファイルを置き換えます。
書き込み前に内容をすべて組み立てるため、失敗しても中途半端なファイルを残しません。

読み込んだテーマは `standalone.json` の `theme` に保存し、次回の起動時に復元します。
このフィールドは省略可能で、古い設定ファイルは組み込みのダークテーマで読み込みます。設定ファイルのバージョンは `1` のままです。

任意のタイル構成、プラグインでの入出力、表示言語の切り替えは、この版の対象外です。

### 計測側の登録（未着手）

メーターごとの計測処理を `MeterProcessor` として登録する形は、まだ実装していません。
現在の `MeterEngine` は、トゥルーピークのオーバーサンプリング、K 特性フィルター、ラウドネスの窓とヒストグラムを 1 か所で持ち、複数のメーターがそれを共有しています。
メーターごとの `process` を trait で登録すると、今は利点より負担が大きくなります。

- 共有している依存（オーバーサンプリング、フィルター）をメーターごとに渡す仕組みが別に必要になり、二重に持つとメモリと計算が増えます。
- `process()` の中で trait オブジェクトを経由すると、オーディオスレッドに仮想呼び出しが入ります。現在は固定の順で直接呼び出しており、確保も動的呼び出しもありません。
- 登録できる新しいメーターがまだ無いため、形を先に決めると、実際の要件（窓の共有、リセットの単位、公開する値）を取り違える恐れがあります。

表示側は、実際に 5 つのタイルが使う形で先に導入しました。
計測側は、共有の依存を持たないメーター（フェーズ 5 のスペクトラムなど）を追加するときに、そのメーターが要る入力と公開する値を決めてから設計します。

## 互換性の方針

| 対象 | 方針 |
|---|---|
| パラメーター ID（`#[id = ...]`） | 一度公開したら変更・再利用しません。保存済みのプロジェクトが壊れるためです |
| 保存キー（`#[persist = ...]`） | 同上。中身の形式を変えるときはバージョン番号を持たせ、古い形式から変換します |
| VST3 クラス ID、CLAP ID | 変更しません |
| レイアウト・テーマのファイル | 外観プリセットは `version` を持ち、未知のバージョンは適用せずに拒否します。設定ファイルの `theme` は省略可能で、古い設定をそのまま読み込めます |

現在のパラメーターは次のとおりです。

| ID | 名前 | 範囲 | 初期値 |
|---|---|---|---|
| `osc_on` | Test Oscillator | オン / オフ | オフ |
| `osc_lvl` | Oscillator Level | -60〜0 dBFS | -18 dBFS |
| `osc_frq` | Oscillator Frequency | 20 Hz〜20 kHz | 1 kHz |
| `lay_preset` | Layout Preset | Standard / Stereo | Standard |

表示専用の `scp_trail`、`scp_auto`、`scp_lr`、`lay_preset` は自動化できません。
`scp_lr` をオンにすると、リサージュの代わりに L/R ベクタースコープを表示します。
`lay_preset` は画面の配置だけを切り替えます。
既存のパラメーター ID と順序は変えず、末尾に追加しています。
プリセット名は配置の呼び名で、準拠する規格や放送用の推奨値ではありません。
